# AI Pixel Copilot · v1.0 交付说明

> 这轮要的是「重新设计架构 + 重新制作 UI」，并且要「灵活性、多功能、能自主扩展、
> 允许接入的模型修改自己、而且保持快速」。本文件说清：做了什么、为什么这么设计、
> 拿什么证明、以及**哪些地方还诚实地说不行**。

## 1. 决策基线（访谈结论，已锁定）

| 编号 | 决策 | 选择 | 为什么 |
|---|---|---|---|
| D1 | 模型自改的边界 | **声明层自扩展** | 模型只能写「能力包」（manifest + 受限 Lua/JS 片段），内核源码碰不到。自扩展不能以「模型能把自己写崩」为代价 |
| D2 | UI 形态 | **工作台式** | 左轨导航 + 主视图 + 右上下文 + composer；终端降级成其中一页，老用户的手感不丢 |
| D3 | 交付范围 | **设计 + 可运行骨架** | 架构白皮书 + 内核 + 新 UI 可运行首版，旧功能平移 |
| D4 | 兼容性 | **数据与快捷键全兼容** | 旧 config.json / bridge/data/* / 10 个算子 / 6 个命令 id / 三个快捷键全部保留 |
| D5 | 「保持快速」口径 | **交互延迟优先** | 首屏 <150ms、输入回显 <30ms、本地工具开销 <50ms、全屏重绘 <8ms |

设计文档：`docs/arch-v1.0.md`（架构契约）、`docs/ui-v1.0.md`（UI 规格）。
两张都是**冻结契约** —— 并行四路施工前先把签名定死，合流只允许"填空"，不允许改形状。

## 2. 架构：三明治内核

### 2.1 一句话

把「内核」压到尽可能小且永不改动，把「能力」全部推出内核之外，变成**可热装载、可自测、
可回滚的能力包**。判据只有一条：**新增一项能力，是否需要改内核？** 若需要，说明分层错了。

### 2.2 结果

```
Aseprite（Lua 5.4）                          Node 桥
┌──────────────────────────────┐          ┌──────────────────────────────┐
│ KERNEL（永不改，约 1100 行）  │          │ KERNEL                       │
│  bus registry host            │          │  server(薄) registry journal │
│  dsl ledger  + kit(视图原语)  │  WS      │ SERVICES                     │
├──────────────────────────────┤ ◀──────▶ │  llm memory styles conv pp   │
│ WORKBENCH（通用三区壳）       │          ├──────────────────────────────┤
├──────────────────────────────┤          │ PACKS  9 个内置包 / 25 工具   │
│ PACKS（模型可写）             │          │ EVOLUTION propose verify     │
│  builtin/{core,ops}          │          │  activate rollback health    │
│  user/<id>（运行时装载）      │          └──────────────────────────────┘
└──────────────────────────────┘
```

依赖严格单向：`packs → workbench → kernel`。反向 import 视为 bug。

### 2.3 关键尺寸

| 模块 | 行数 | 职责 |
|---|---|---|
| `extension/kernel/bus.lua` | 93 | 事件总线，handler 抛错被捕获记入 journal |
| `extension/kernel/registry.lua` | 120 | 五种 kind 的注册表 + fingerprint（懒构造） |
| `extension/kernel/host.lua` | 144 | **唯一**允许调 `app./Sprite{/Image{` 的地方 |
| `extension/kernel/dsl.lua` | 107 | 受限沙箱 + `runBounded` 超时护栏 |
| `extension/kernel/ledger.lua` | 429 | 账本、快照、回滚、health、JSONL journal |
| `extension/kernel/init.lua` | 218 | 组装、包装载、包自测裁决、`invoke` 限时入口 |
| `extension/kernel/kit.lua` | 420 | 视图原语（纯 GC + 命中测试，无可测依赖） |
| `extension/lib/workbench.lua` | 1249 | 三区壳，只认 registry，不认识具体视图 |
| `bridge/src/tools.mjs` | 1003 → **167** | TOOLS 变成内置包的聚合结果 |

`panel.lua` 从 1700 行单体，拆成 `views/console.lua`(381) + 三区壳 + 六个视图，
自身只剩 `+29/−73` 的转发层。**四形态一行没动。**

## 3. 自扩展闭环（这条是本轮的核心）

```
观察 ─────▶ 提议 ─────▶ 验证 ─────▶ 启用 ─────▶ 现网表现
journal    propose_pack  verify_pack  activate     pack_health
gaps.md    (写 staging)  (子进程跑)   (Lua 热装载)  失败率超阈值
"做不到"自述                         + 自动快照      自动回滚
```

### 3.1 五条护栏（每条都有断言，缺一条这条需求就是假的）

| # | 护栏 | 实现 | 测试 |
|---|---|---|---|
| 1 | 不可写内核 | staging 之外的路径写入被白名单拒（含 `..`、盘符绝对路径、藏在中段的 `..`） | `evolution_test` |
| 2 | 必须自测 | 桥侧子进程数**真实断言**；Lua 侧 `runPackTests` 数 `t.ok/t.eq` 调用次数，`asserts==0` 一律判没验过 | 两侧各有断言 |
| 3 | 必须同名 | `manifest.ops[].name` 必须在注册表里真实存在且可调用 | `evolution_test` |
| 4 | 必须可回滚 | 激活前自动快照，最多留 3 版，装载失败自动回退 | `evolution_test` |
| 5 | 预算 | 单轮最多 3 次 propose；单包 ≤200 行 / 32KB | `evolution_test` |

### 3.2 本轮补上的三条（都是施工中发现、会真正咬人的）

1. **沙箱超时**：`Dsl.runBounded` 用 `debug.sethook` 限步（CPU 时钟，每 1000 指令查一次），
   保存/恢复外层 hook 以支持嵌套。**理由**：允许模型写能力包之后，一个 `while true do end`
   就能卡死 Aseprite 的 UI 线程 —— 没有这条护栏，自扩展能力等于自毁能力。
2. **运行时限时调用**：`K.invoke(kind,id,...)` 让**包注册的算子**也走预算。装载与自测受控
   还不够：算子是在用户点击/模型调用时执行的，那才是死循环最可能出现的形态。
3. **自扩展对模型自己可见**：`buildCapabilities` 增加 `can.evolve` 列出 6 个手柄。
   否则模型问「你能做什么」看不到 `propose_pack` —— 它不会知道自己能改自己。

### 3.3 保持快速的三条硬手段

- 能力包**不进常驻 prompt**，模型用 `list_capabilities(query)` 按需检索（tool-search 模式）。
- schema 懒构造：`fingerprint()` 不变不重算。
- Lua 侧**脏区重绘**：rail / context / main / composer / titlebar 五个区独立失效，
  输入回显只脏 composer，滚动只脏 main，唯一全标脏是窗口尺寸变化。

## 4. UI：从终端到制图台

### 4.1 设计立场

不是聊天框，是**制图台**：直角、无阴影、1px 发丝线、4px 栅格、数字等宽对齐。
**accent 从当前 sprite 调色板取彩度最高的颜色派生** —— 工具永远和它在编辑的那张图同气质。

### 4.2 结构（实测 rect，900×484 画布）

```
titlebar   0,  0, 900, 30      ◆ AI PIXEL COPILOT | 001.ase | ● 状态 | ▣◫－×
rail       0, 30,  56, 414     7 个视图图标，当前项左侧 2px accent 竖条
main      56, 30, 604, 414     会话 / 画布 / 风格 / 记忆 / 扩展 / 画廊 / 设置
context  660, 30, 240, 414     文档（名称/尺寸/图层/帧）· 状态（待办/本轮）
composer   0,444, 900, 40     ▶ 说点什么，或敲 / 叫命令…     ⏎ 📎 ⏹
```

右上下文行距实测 18px、组间 8px，与规格一致。

### 4.3 键盘可达（不用鼠标能走完全流程）

`/` 聚焦并唤起补全 · `Ctrl+K` 命令面板 · `Alt+1..6` 切视图 · `Alt+C` 折叠上下文 ·
`Esc` 三级退出（关补全 → 关弹层 → 中断轮）· `Tab` 四区轮转。

### 4.4 空状态是设计的一部分

- 会话空：「说一句你想改的。比如「把这层的红色换深一点」」
- 扩展空：「还没有自建能力包。让 AI 看看 gaps.md，它知道自己缺什么。」+ 让它提议
- 断连：顶部红条 + 原因 + 一条可复制的起桥命令 + 重试

## 6. 诚实清单（做不到 / 有代价 / 没做完的）

1. **只给宿主用的超时挡不住 C 层阻塞**。`runBounded` 按 VM 指令数计，包卡在
   `io.read` 阻塞或等原生弹窗时 hook 不会打断。桥侧 `verify` 用子进程硬超时兜住了
   （实测 1245ms 杀掉死循环），Lua 侧挡的是最可能出现的 `while true do end`。
2. **Lua 侧的裁决没有消费点**。`runPackTests` 现在给出 `out.ok`，但 `loadPack` 不因
   自测没过就拒装 —— 闸门留在 activate 那一步是**有意的**：硬拒会让"正在编辑的包"完全不可见。
3. **纯 Lua 包（无 bridge 工具）没有完整的 verify 路径**。桥侧 verify 要求 `tests.mjs`
   存在；Lua-only 包要么补一个 `tests.mjs` 存根，要么等 verify 回落到 `runPackTests`。
   这条是 roadmap，不是 bug。
4. **授权框从 3~4 个变 4~5 个**。`ledger` 的 install/rollback 需要 `os.remove`/`os.rename`，
   新增的是 `kernel/ledger.lua` 那一次。为了不给回滚留陈旧文件，这个代价值得。
5. **`resolveCels` 去重是真 bug 修正，属行为变更**。v0.5.9 拿 cel userdata 当 key，
   而每次 `:cel()` 拿到的是不同包装对象 —— 等于没去重，同一层会被算子改两遍。
   现在用「层名#帧号」做稳定键。这是**有意的**行为修正，不是等价重构。
6. **并行三路是"契约先行"才成立的**。先冻结 `arch-v1.0.md` / `ui-v1.0.md` 的签名，
   三路才能同时动工且合流只填空。没有这一步，1135 行的 workbench 与 6 模块内核不可能并行。

## 8. 迭代二：真机反馈修复（用户实测「面板点击不了」）

第一版交上去后用户重启实测，反馈面板点不动。查下来不是绘制问题，是**两层断**：

| 层 | 事实 | 后果 |
|---|---|---|
| 功能断（主因） | `agent.lua:186` 的 `self.panel` 永远绑旧 `lib.panel`；`main.lua` 只是另外 new + show 一个工作台，从不把 agent 的 panel 换过去 | 界面是工作台，**所有消息/状态/提问写进一个不显示的旧对象** → 面板是死的 |
| 输入断 | 旧面板的激活点在 `onmouseup`（`_onCanvasMouseUp` 才 `_runMenuIndex`），工作台只在 `onmousedown` 里激活，且坐标裸传 | 点击要么不生效，要么 `ev.x` 为 nil 时在 onmousedown 里抛错穿进 C++ |

为什么换不过去：agent 调用 panel 的 **25 个方法**，工作台只实现 6 个 —— 直接换会一堆 `attempt to call a nil value`。

### 修复

1. 新增 `extension/lib/panel_adapter.lua`（341 行）：实现全部 25 个方法 + `opts` 字段。能映射的映射
   （`openMenu`→`openPalette`、`setThinking`→`setBusy`、`replayLines`→`setHistory`、`setAsk`→`wb.state` 卡片），
   只能交旧面板的（原生弹窗、小面板、矫正队列）回落旧 panel，两边都没有才 no-op 并记 `unsupported[]`。
   **每个入口都 pcall，一个方法都不抛。**
2. `main.lua` 新增 `swapAgentPanel(a, wb)`：工作台 show 成功后 `a.panel = 适配层`；失败一行带真错误的 note，回落行为一字不变。
3. 点击语义照旧面板改：`mousedown` 只管焦点、`mouseup` 才激活、右键不激活、坐标 `tonumber` 兜 0、整体 pcall → `lastInputError`。

### 这一轮暴露的两个流程问题（写下来防复发）

1. **我的验收方法有洞**：GUI 截图里我用 `wb:log()` 直接喂数据，绕过了 agent 这条真链路 —— 面板画得出来、点不动，
   而我的证据看着是绿的。现在补了 `panel_contract_test`（从 agent.lua 源码静态提取 25 个方法，逐个断言可调）和
   `workbench_click_test`（真 kernel + core 包视图 + `_bounded` 包装这条真链路）。
2. **契约里没写「工作台必须实现 panel API」**：`ui-v1.0.md` 只规定视图与布局，漏了「谁能替agent 的 panel」这条接缝。
   并行三路各做各的时候，这条缝没人认领。

### 红证明（测试不是摆设）

- 把适配层 `setContext` 改名 → contract 测试 3 条红；改回 → 58 通过。
- 把 `onmouseup` 从 canvas handlers 摘掉 → click 测试红；改回 → 31 通过。
