# v0.5.9 计划：二进制通道 / 超时 / 锐化与对比 / 小窗贴角

用户的四句话（原话）：

> 现在超时限制是不是太严格了。最小化应该最小化为一个悬浮窗，如果做不到，就把最小化窗口默认放在右下角。
> 200x200 以内的画面修改会消耗很多token吗？我想要它帮我锐化边缘，加强明暗对比它做不到

## 0. 先验证（动手前查出来的事实）

| 说法 | 实情 |
|---|---|
| "超时太严格" | **两处都是真的**：单次 HTTP 120s（慢的推理模型 + 大提示词会超）；整轮 180s（一轮最多 24 步、每步一次 HTTP，180s 连正常多步作业都跑不完）。而且超时抛的是 fetch 的 `AbortError`，用户看到的是 "This operation was aborted"。 |
| "锐化/对比做不到" | **不是模型不肯做，是根本没有这两个算子**。`ops.lua` 的 OPS 表只有 8 个，工具 schema 的 enum 也只有 8 个 —— 模型连"能锐化"这件事都看不见。 |
| "最小化不是悬浮窗" | 小窗（`small` 形态）**本来就是**一个独立的无标题栏……不，是**带标题栏的独立对话框**（和主面板同一个 dlg，换了尺寸），可以拖。缺的只是**默认位置**：它原本贴"右侧、垂直居中"，正对着画面中央。 |
| "200x200 会烧很多 token 吗" | **不会**。像素数据从不进模型上下文（`canvas_info` 只给最多 12 个颜色 + 尺寸）。每步固定开销才是大头：工具表 16.4KB ≈ 4.1k token × 步数。 |

顺手挖出来的一个真 bug（和上面都无关，但更严重）：`ws.lua` 的 `sendBinary` 把头部帧的
**语义 `type` 覆盖成了 `"binary_header"`**，桥认不出这个 type → 上传和 `get_canvas`
两条路全死。这条就是 `bridge/data/gaps.md` 里 #1「读不到画布」的根因。

## 1. 做了什么

### 1.1 二进制通道（根因修复）

`extension/lib/ws.lua`：`sendBinary` 只加 `binary = true` 标记，**不动 `type`**。
桥侧 `sendImport` 同步改成发 `binary: true`。

- 新测试 `tests/lua/ws_test.lua`（20 项）：假 socket + 直接喂 `conn:_receive(...)`，
  钉住帧形状（type 保留 / 不是 binary_header / 调用方那张表没被改 / 头帧配对后清空 /
  普通消息照旧分发 / 孤儿负载不炸）。
- `bridge/test/selftest.mjs` 的假 Aseprite 以前说的是**桥的方言**（所以从没测出这个 bug），
  现在改成**真客户端的方言**，并在注释里写明为什么。

### 1.2 超时

- `bridge/src/llm.mjs`：新增 `RequestTimeout`（带 `timedOut` / `timeoutMs`），
  只把"自己计时器踢的那一脚"翻译成它；用户中断 / 整轮中断照旧走 `TurnAborted`。
  默认 120s → **180s**。
- `bridge/src/server.mjs`：整轮默认 180s → **600s**；两条超时都给友好文案
  （`llmTimeout` / `abortTimeout`，带秒数，指向设置窗）。
- 两个值都能在**面板设置窗**里改（界面按秒填，桥收毫秒）：
  单次 10s–1800s，整轮 30s–3600s。
- `i18n.lua` 新增 `i18n.render(key, args, fallback)`：带 `%d` 的文案按实参格式化；
  认不出键、缺实参、格式化失败都退回原文 —— **绝不把 `%d` 显示给用户**。
  回放行也带上 `i18nArgs`（`history.pushLog` 第 4 个参数），重连回放时数字还在。

### 1.3 两个新算子

| 算子 | 做什么 | 参数 |
|---|---|---|
| `sharpen` | 3x3 非锐化掩模（unsharp mask），逐通道 | `amount`（默认 1，2-3 激进）、`threshold`（0-255 忽略带，保护平色与抖动网点）、`region` |
| `contrast` | 以 `pivot`（默认 128 中灰）为轴把每通道乘开 | `amount`（默认 1.3 = +30%，<1 是压平）、`pivot`、`region` |

两条硬规矩（都有测试钉着）：

1. **alpha 一律不动**，全透明像素一律跳过 —— 像素画的"锐"是 RGB 的对比，不是透明度。
2. `sharpen` 的 3x3 均值**只统计不透明邻居**。把透明邻居算成 0 的话，剪影边缘会被整体
   提亮一圈，在透明背景上就是一圈脏边（像素画里最显眼的毛病）。

`ops.names`（发给桥、进 `can.edit_ops`）、`tools.mjs` 的 enum、工具说明三处必须一致：
由 `tests/lua/ops_test.lua` 的"算子名单 == 契约"和 `bridge/test/tools_test.mjs` 的 P15 段
两头钉住。系统提示加规则 **12c**（"边缘发虚 → sharpen；发灰发平 → contrast"）。

### 1.4 小窗贴右下角

`panel.lua` 把贴位算式抽成纯函数 `panel.anchorFor(mode, W, H, bw, bh)`：

- 底边栏：水平居中贴底
- 侧边栏：贴右、垂直居中
- **小窗：贴右下角**（原来是右侧居中，正对着画面中央）

另外只在**真的换形态**时才贴位（`mode ~= prev`）—— 重连、保存设置都会重复
`setMode(同一个形态)`，那不该把用户拖到别处的窗口拽回来。

## 2. 不做的事

- 不做"记住用户拖到哪儿"：小窗每次进入都回到右下角。位置状态要落盘、要处理多显示器，
  收益不抵复杂度；拖一下的成本远低于此。
- 不把 `sharpen` 做成卷积核参数（`matrix`）：模型容易写出跑偏的核，而"边缘发虚"这个
  需求 unsharp mask 就够，参数越少越不容易用错。
- 不给 `contrast` 加"只调亮度不调色相"的开关：逐通道是像素画手绘时的直觉做法
  （把暗部再压暗一档），要保色相就用 `pivot` 微调。

## 3. 验收

- 新算子：8x8 灰阶边界上算出确切数字（100/160 的边界 → 80/180；contrast 1.3 → 92/170），
  不靠看截图。
- 超时：假 LLM 卡死 → 断言提示是 `llmTimeout` + 带秒数 + warn 级 + **文案里没有 aborted**；
  `set_config` 越界要夹（5000ms → 10000ms，99999999ms → 3600000ms）。
- 小窗：`anchorFor` 的四个分支 + GUI 探针打出真窗口的右边距/底边距（应为 0）。
