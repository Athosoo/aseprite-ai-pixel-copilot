## 1. 缺口清单（这一轮要做的）

### G1 桥侧对 `open_document` / `list_workspace` 几乎没有测试（**最高优先级**）

`tools_test.mjs` 里只有 1 处提到（`want` 列表里的工具名），`selftest.mjs` 里 0 处。
这正是 v0.4.0 踩过的盲区：**桥发的字段名和 Lua 读的对不上，两边单测都全绿**。
→ 补：tools_test 转发断言（消息类型 / 字段）+ selftest 场景（端到端问一次能不能打开）。

### G2 底边栏看不到"正在执行的指令"

底边栏画布高度 44 → 只放得下 2 行（状态 + 输入），"最后一行输出"那行被 `rows >= 3`
的条件挡掉了 —— 而用户要的正是"作画时能看到正在执行的指令"。
→ 改：底边栏高度按 3 行算（状态 + 最后一行输出 + 输入），约 62px。

### G3 形态不持久

`setMode` 只在内存里，重启 Aseprite 回面板。
→ 改：形态存进 `config.json` 的 `ui.mode`（桥侧 `configPayload` / `set_config` 同步），
启动时按它恢复。

### G4 打开文档只有 AI 能触发，面板里没有入口

用户想自己开一个文件时只能走 Aseprite 的 File > Open，或者走「选图」（那条路会进矫正队列）。
→ 改：菜单加「打开文件…」→ 原生文件选择器 → **直接打开**（不进矫正队列）。

### G5 "完美融入"：主题色实测读不到 → 给用户一个填色口

本轮再证一次：`app.theme.color["window_face"]` 和 `app.theme.color["zzzz"]` 都返回
`0,0,0`（真名字和假名字一样 = 就是个兜底对象），`app.theme` 只有 `color` 这一个成员。
→ 所以：① 保留自绘深色（已接近 Aseprite 默认深色主题）；
② 设置里加「栏底色」输入框（十六进制），用户可以填自己主题的底色来贴合。

### G6 `capabilities` 少两件当前状态

模型不知道"现在有没有工作区""现在是面板还是栏"，回答"能不能备份"时会含糊。
→ 改：`capabilities` 带上 `workspace: {enabled, root}` 与 `uiMode`，
并把"能打开哪些后缀"明确列出来。

### G7 `list_workspace` 不带文件大小

`app.fs.fileSize` 实测可用。
→ 改：每项带 `size`，模型能说出"那个副本 12 KB"。

## 2. 执行顺序与验收

1. **G1**（先做，因为它是"现在的东西可能悄悄坏掉"的风险）
   验收：`tools_test` 对 `open_document`/`list_workspace` 有转发断言；
   `selftest` 新场景里模型调 `open_document` 能拿到 `{ok:true, width, height}`。
2. **G2 + G3 + G5**（都在面板/配置层，一起改一起测）
   验收：`panel_test` 断言底边栏高度 ≥ 3 行、形态能序列化/恢复；
   真 GUI 探针打印新的底边栏尺寸并截图，肉眼确认能看到"最后一行输出"。
3. **G4 + G6 + G7**
   验收：`workspace_test` / `tools_test` 覆盖新字段；菜单里有「打开文件…」。
4. 全量回归（Lua + 桥）+ 升版 **0.5.1** + 重打包 + 本地安装 + 提交。

## 3. 不做的事（明确划掉）

- **不重写已经实现的 4 条主体**——只补上面 7 个缺口。
- **不做真·停靠**：Aseprite 没有 dock 接口、读不到主窗口位置（`app.window` 只有
  width/height），这是硬限制，不是没做。
- **不去猜主题色**：已用"真名 vs 假名返回值相同"证明读不到，所以走"用户可配置底色"。
